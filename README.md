# Аванс по договору

Скрипт на Python строит отчёт на выбранную дату: по каждой работе цена, сколько уже зачтено и сколько осталось, и итог по каждому договору. Деньги считаются в `Decimal`, до копейки.

Исходные файлы лежат в `data/`: договоры, работы и платежи. Готовый отчёт на контрольную дату 10.11.2026 уже записан в `out/`. Повторный запуск перезаписывает эти два CSV.

## Как запустить

Нужен Python 3.9 или новее. Отдельные пакеты не ставятся, хватает стандартной библиотеки. На macOS команда обычно называется `python3`.

```bash
python3 report.py --as-of 2026-11-10 --data data --out out
```

- `--as-of` — дата отчёта. Формат `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ`. По умолчанию `2026-11-10`. День включается целиком.
- `--data` — папка с `contracts.csv`, `works.csv` и `payments.csv`. По умолчанию `data`.
- `--out` — папка для отчёта. По умолчанию `out`. Она не должна совпадать с `--data`, иначе скрипт откажется писать поверх выгрузки.

Журнал шагов пишется в stderr. Код 0 — оба файла записаны. Код 2 — не разобрались аргументы. Код 1 — нет файла, пустой файл, нет прав, битая строка или папка отчёта совпадает с папкой данных.

Проверки:

```bash
python3 -m pytest tests/test_report.py -q
```

## Что получается

В `--out` два файла. Разделитель — запятая, суммы с точкой и двумя знаками, кодировка UTF-8 с BOM, чтобы кириллица открывалась в Excel.

`works.csv` — одна строка на работу:

| Колонка | Что это |
|---|---|
| дата | День, на который посчитан отчёт. |
| договор, подрядчик | Договор и имя подрядчика. |
| работа, название | Номер и название работы. |
| состояние | На эту дату: `принята`, `в плане` или `отменена`. Берётся из дат приёмки и отмены, не из колонки `status` в выгрузке. |
| цена | Цена работы. |
| выплачено | Сколько аванса и привязанных платежей уже зачтено на эту работу, не больше цены. |
| осталось | Цена минус выплачено. У отменённой работы остаток 0. |
| переплата | Деньги, привязанные к работе сверх её цены. На 10.11.2026 таких сумм нет. |

`contracts.csv` — одна строка на договор:

| Колонка | Что это |
|---|---|
| сумма договора | Сумма из `contracts.csv`. |
| живой объём | Сумма цен работ без отменённых. |
| принято актами | Сумма цен работ, уже принятых на дату отчёта. |
| ушло денег | Платежи, у которых `paid_at` не позже даты и возврат к этой дате ещё не прошёл. Очередь сюда не входит. |
| разнесено по работам | Часть этих денег, разложенная по строкам работ. |
| свободный аванс | Деньги уже ушли, но на принятые работы ещё не легли. |
| остаток | Живой объём минус «ушло денег». Может быть отрицательным, если выплатили больше объёма. |
| в очереди | Платёж заведён, но деньги на эту дату ещё не ушли. |

«Выплачено» в строке работы — это зачёт общего аванса, а не отдельная платёжка. Платёж с пустым `work_id` сначала закрывает принятые работы по дате приёмки. Хвост остаётся свободным авансом договора и на ещё не принятые работы не кладётся. Текст назначения платежа в расчёт не идёт.

## Цифры на 10.11.2026

По студии «Свет» (D-1): ушло 315 000, свободный аванс 15 000, остаток 185 000, в очереди 150 000. Съёмка аксессуаров отменена, её 100 000 в остаток не входят. Три принятые съёмки закрыты.

По Ивану Петрову (D-2): ушло 75 000, свободный аванс 25 000, остаток 15 000. Логотип и фирменный стиль закрыты. Упаковка на эту дату ещё не принята: в выгрузке у неё уже стоит `done`, но дата приёмки — 11.11.

На 12.11.2026 тот же запуск с `--as-of 2026-11-12` показывает по D-2 остаток −5 000 и свободный аванс 5 000: к этой дате принята упаковка и ушёл последний платёж.

Почему выбраны именно эти правила и что съедет в цифрах при другом выборе — в `DECISIONS.md`. Короткая записка, что подтвердить бухгалтеру, — в `accountant.md`. Журнал сессии — в `transcript/`.
